# Devlog

## 사내 GitOps 레포를 포트폴리오용으로 익명화하기  (2026-09-18)

### Problem
1,400여 개 파일(Terraform/Terramate, Helm values, ArgoCD, K8s 매니페스트, 사내 앱 코드, 운영 문서)로 이뤄진 GitOps 레포를 회사 식별 정보 없이 공개 가능한 사본으로 만들어야 했다. 회사명·도메인·클라우드 계정 ID·리소스 ID·제품명·사람 이름이 파일 내용과 경로 양쪽에 섞여 있었다.

### Expected
- 결정적(deterministic) 치환: 같은 원본 값은 어디서든 같은 가짜 값으로 바뀌어 파일 간 참조가 깨지지 않을 것
- 구조·패턴·운영 노하우는 유지하고 식별 정보만 제거할 것
- git history는 버리고 fresh commit으로 시작할 것 (과거 커밋에 남은 값까지 지울 수 없으므로)

### Cause
정규식 기반 1차 치환만으로는 부족했다. 4개 영역(문서 / 에이전트 설정 / K8s / Terraform+앱)으로 나눠 병렬 감사한 결과 아래 유형이 누락돼 있었다.

| 누락 유형 | 예 | 왜 놓쳤나 |
|---|---|---|
| 복수형·변형 | `/items` (단수 `item`만 매핑) | 매핑을 단어 단위로만 정의 |
| `_` 경계 식별자 | `foo_ecr_<name>_dev` | `\b`가 `_`를 단어 문자로 취급 |
| 한글 제품명 | 영문 서비스명만 매핑, 한글 표기는 미매핑 | 언어별 표기 목록을 따로 안 만듦 |
| 패턴 밖 클라우드 ID | ElastiCache 엔드포인트 랜덤 서브도메인, `vol-`, `rtb-`, 자동생성 IAM role 이름 | `sg-/vpc-/subnet-/i-/Z…/UUID`만 목록화 |
| 데이터 속 조직 정보 | 사내 앱 seed SQL·프론트 상수에 하드코딩된 조직도·직원 닉네임 | 정규식은 "이름"을 모름 — 의미 감사 필요 |
| 문서용 아닌 실 값 | 스프레드시트 ID, dev 환경 평문 시크릿 | 값 형태가 랜덤 문자열이라 패턴화 불가 |

### Attempts
1. **LLM 에이전트에게 파일별 편집 위임** — 검토했으나 기각. 1,400개 파일 편집은 토큰 비용·속도·일관성 모두 스크립트보다 나쁨.
2. **정규식 1회 치환 후 grep 검증 = 완료** — 1차 시도. 검증 grep이 0건이어도 위 표의 누락이 남아 있었다. grep 검증은 "내가 아는 패턴"만 검증한다는 한계.
3. **정규식 치환(기계) + 의미 감사(에이전트 병렬) + 2차 치환** — 채택.

### Decision
- 치환 매핑은 사람이 설계하고, 실행은 Python 스크립트가 결정적으로 수행
- 검증은 두 층: (1) 패턴 grep, (2) 디렉토리 4분할 병렬 의미 감사(읽기 전용, 발견만 보고, 수정 권한 없음)
- 감사 결과를 2차 규칙으로 흡수해 재실행. 규칙에 못 담는 데이터(조직도 상수)는 가짜 데이터로 재작성
- 원본↔가짜 매핑표는 **레포 밖**에만 보관 (매핑표 자체가 원본명 노출)

### Why
- 스크립트: 결정성·재현성. 같은 입력이면 같은 출력이라 재실행·diff가 가능
- 의미 감사만 에이전트: 판단이 필요한 부분(이 문자열이 실명인가?)만 사람 수준 판단에 맡김. 편집 권한을 안 준 이유는 감사자가 조용히 수정하면 무엇이 왜 바뀌었는지 추적이 안 되기 때문
- 병렬 4분할: 범위가 겹치지 않게 나누면 한 에이전트 컨텍스트 안에 들어가고, 총 소요시간이 1/4
- trade-off: 감사 에이전트 토큰 비용(합계 약 80만 토큰). 수동 검토 대비 저렴하다고 판단

### Result
- 원본 1,427 파일 → 1,375 파일 (tfstate·업무일지·재무 스킬·사진 등 52개 제외)
- 경로 rename 874건, 1차 치환 약 4,300 hit, 2차 치환 약 150 hit
- 최종 패턴 grep 0건, 의미 감사 HIGH 항목 전부 해소

### What I Learned
- **`\b`는 `_`를 못 끊는다.** 식별자 치환은 `(?<![A-Za-z0-9])word(?![A-Za-z0-9])`로 경계를 직접 정의해야 snake_case 안의 토큰을 잡는다
- **grep 검증 0건 ≠ 안전.** 검증 패턴은 치환 패턴의 거울이라 같은 사각지대를 공유한다. 독립적인 의미 감사가 필요
- **가장 위험한 누출은 "설정"이 아니라 "데이터"였다.** 사내 앱 seed·상수 파일에 조직도가 통째로 있었다. 인프라 레포라도 앱 코드가 섞여 있으면 데이터 파일을 우선 봐야 한다
- 클라우드 리소스 ID는 접두사 목록으로 관리하지 말고, `<prefix>-<hex 17자리>` 형태를 일반화해서 잡는 게 안전하다
- 매핑표·스크립트는 산출물이지만 원본명을 담고 있으므로 결과 레포에 넣으면 안 된다

## 익명화 2차 감사 — 정규식·gitleaks가 놓친 것들  (2026-09-22)

### Problem
1차 익명화를 마친 포트폴리오 레포 3개(ECS 시대 Terraform / EKS GitOps / Helm 매니페스트)를 공개 전에 재감사했다. "패턴 grep 0건" 상태에서 실제 시크릿·식별자가 얼마나 남았는지가 질문이었다.

### Expected
gitleaks 통과 + 패턴 grep 0건이면 공개해도 될 것이라고 봤다.

### Cause
아래가 남아 있었다. 전부 원본 레포와 값을 대조해 실값임을 확인했다.

| 유형 | 어디에 | 왜 놓쳤나 |
|---|---|---|
| dev 환경 평문 시크릿 (IdP `secret_key`, DB 비밀번호, PM 도구 `secret_key`) | Helm values `dev.yaml` | 1차에서 "랜덤 문자열이라 패턴화 불가"로 분류하고 미처리. gitleaks는 잡았지만 실행하지 않았음 |
| 관리자 비밀번호 bcrypt 해시 | GitOps 도구 values | "해시는 비밀번호가 아니다"로 오판. 오프라인 사전 공격 대상 |
| 모니터링 SaaS API 키 (32 hex) | Terraform 변수 `default` | gitleaks generic 룰은 키워드 문맥이 필요. 변수명 `dd_api_key`는 안 걸림 |
| SAML IdP 메타데이터의 서명 인증서·서명값 | tfvars heredoc | 공개키라 시크릿은 아니지만 실 IdP 인스턴스와 1:1로 매칭되는 지문 |
| 1차가 놓친 ID 형태 | `sgr-`(SG rule), ALB listener/TG 16hex, 콘솔 자동생성 role 접미사 8자, 리소스명 끝 타임스탬프 26자리, epoch ms | 접두사 목록 방식의 한계 — 1차 devlog에서 지적한 것과 같은 실수 |
| 약어 변형 | `fm-`는 치환됐지만 `fm/`는 잔존 | 경계를 `-`로만 정의 |
| 고유명사 | 제품 브랜드, 커머스 SaaS 벤더명, 분석 SaaS org id, 회사 약어인 Jira 프로젝트 키, 오타가 그대로인 ECR 이름 | 정규식은 고유명사를 모름 |
| 조직 정보 | 에이전트 설정(`.claude/CLAUDE.md`, `AGENTS.md`), 앱 seed·프론트 상수 | 인원수·내부 위키 경로·재무 워크플로 — 인프라 코드엔 없고 설정 파일에만 있음 |
| 스크럽 부작용 | 브라우저 버전 `98.0.4758.70`, 컨테이너 태그 `2.8.0.0`이 `203.0.113.x`로 바뀜 | IPv4 정규식이 4-옥텟 버전 문자열을 구분 못 함 |
| git history | 스크럽 수정 커밋 이전 커밋에 원본값 잔존 | "history 버림"을 최초 스냅샷에만 적용하고 그 위에 수정 커밋을 쌓음 |

### Attempts
1. **gitleaks `git` 모드(전체 history)** — 평문 시크릿은 검출. 32hex API 키·bcrypt·인증서는 미검출
2. **패턴 grep** (12자리 계정, 리소스 접두사, 공인 IP, 이메일, 도메인) — 대부분 플레이스홀더 확인. 하지만 검증 패턴은 치환 패턴의 거울이라 사각지대가 같음
3. **고엔트로피 토큰 스캔 + 원본 레포 대조** — 채택. 20자 이상·Shannon entropy ≥ 3.9(대소문자+숫자 혼합은 ≥ 4.3) 토큰을 뽑아 원본 레포에 `git grep -F`. "원본에도 있는 고엔트로피 문자열"은 거의 확실히 실값. API 키·bcrypt·인증서가 전부 여기서 잡혔다
4. **읽기 전용 의미 감사 에이전트 2개 병렬** (문서·에이전트 설정 / Terraform·Helm) — 오탐도 있었다. 본인 GitHub 핸들, 1차에서 넣은 플레이스홀더 코드명을 "실명"으로 보고. 원본 대조로 걸러냄

### Decision
- 시크릿은 `REPLACE_ME_*`, bcrypt는 공식 문서의 예시 해시, ID는 자릿수를 유지한 `0`으로 치환
- 값 비교는 항상 **해시로만** (원본·사본 값의 sha 앞 8자). 시크릿 평문은 터미널에도 띄우지 않음
- 업종 용어(사업 도메인을 드러내는 서비스·엔티티 이름, 한글 주석 포함)도 중립 도메인(예약 플랫폼·커머스)으로 결정적 치환. 처음엔 가독성을 이유로 유지하려 했으나, 회사명 없이도 업종+지역+기술스택 조합으로 회사가 좁혀진다고 판단해 변경. 내용과 경로에 같은 매핑을 한 번에 적용. 매핑표는 레포 밖에만
- history는 orphan 커밋 1개로 squash 후 force-push. 이전 history는 로컬 백업 태그로만 보관
- 공개 전 실 환경 시크릿 로테이션 권고. private 레포였어도 GitHub에 올라간 시점부터 유출로 가정

### Why
- 엔트로피 + 원본 대조: 패턴을 모르는 시크릿을 잡는 유일한 방법. 오탐(go.sum 해시, IAM 정책명, 업스트림 차트의 known_hosts)은 파일 종류 제외 목록으로 충분히 걸러짐
- bcrypt 치환: salt가 있어 rainbow table은 안 되지만 admin 비밀번호는 사전 공격 대상. "해시니까 괜찮다"는 틀린 가정
- squash: 스크럽 수정 커밋을 쌓으면 diff가 원본값을 그대로 보여준다. "무엇을 지웠는지"가 history에 남는 것 자체가 유출

### Result
- 3개 레포 약 320개 파일 수정(경로 rename 241건 포함). 실값 시크릿(IdP secret_key·DB 비밀번호·PM 도구 secret_key·모니터링 API 키)과 admin bcrypt, IdP 인증서 제거
- gitleaks 재스캔: 업스트림 차트 주석의 예시 값만 잔존
- 엔트로피 재스캔: 원본과 겹치는 고엔트로피 토큰은 go.sum 해시·IAM 정책명·known_hosts 뿐

### What I Learned
- **gitleaks 통과 ≠ 시크릿 없음.** 키워드 문맥 없는 32hex, bcrypt, 인증서는 안 잡힌다. 엔트로피 스캔을 원본 대조와 붙여야 한다
- **원본 레포가 남아 있으면 그게 최고의 검증 도구다.** "이 값이 원본에도 있나?"는 실값/플레이스홀더를 정확히 가른다. 감사 에이전트의 오탐(플레이스홀더를 실명으로 보고)도 같은 방법으로 걸러진다
- **IPv4 정규식은 버전 문자열을 먹는다.** `\d+\.\d+\.\d+\.\d+`는 `2.8.0.0-alpine`, `Chrome/98.0.4758.70`에 걸린다. 앞뒤가 `[A-Za-z/:]`이면 제외해야 한다
- **에이전트 설정 파일이 인프라 코드보다 더 많은 조직 정보를 담는다.** 인원수·위키 경로·재무 워크플로는 코드에 없고 `.claude/`·`AGENTS.md`에 있었다
- **스크럽 수정 커밋을 쌓지 말 것.** 매 수정마다 squash — diff 자체가 매핑표다
- **업종 용어 치환은 내용·경로 동시에, 한 매핑으로.** 따로 하면 ArgoCD `path`·values 경로 같은 cross-repo 참조가 깨진다. camelCase 변형(`FooBar` 형태)은 lower/Title/UPPER 세 형태 규칙에서 빠지므로 대소문자 무시 잔존 검사가 필수
